## 개념

### Member (회원)

- 정의: 서비스에 가입한 사용자.
- 상태: 활성, 탈퇴. (정지는 미정)
- 정책: 이메일과 비밀번호로 가입한다. 닉네임은 의견 작성자 표시에 쓰인다.
- 불변 조건: 이메일은 유일하다. 닉네임은 유일하며 2~12자(가안)다. 비밀번호는 해시로만 저장한다.
- 역할: `USER`, `ADMIN`.
- 차단: 의견 카드에서 작성자를 차단한다(`POST /api/opinions/{id}/author-block`, 이미 차단했으면 그대로 204). 한쪽 방향이며 차단한 회원의 의견 목록(`GET /api/issues/{id}/opinions`)에서만 빠진다. 결과 집계·추천 수·신고에는 영향이 없다. 자기 자신은 차단할 수 없다(400). 목록 `GET /api/members/me/blocks`는 회원 ID 없이 차단 ID·닉네임(탈퇴했으면 '탈퇴한 회원')·차단 시각을 주고, `DELETE /api/members/me/blocks/{blockId}`로 해제한다. 코드: `member/domain/entity/MemberBlock.java`
- 탈퇴: 비밀번호를 확인한 뒤 탈퇴한다. 이메일·닉네임·비밀번호를 지우고(null) 탈퇴 시각을 남긴다. 모든 리프레시 토큰을 폐기하고, 만료 전 액세스 토큰도 거부한다(인증 요청마다 회원 상태 확인). 투표·의견·신고는 남고 의견 작성자는 "탈퇴한 회원"으로 표시한다. 지운 이메일·닉네임으로 다시 가입할 수 있다.
- 결정되지 않은 질문: 닉네임 변경 허용 여부, 이메일 인증 여부, 탈퇴 회원 행의 보관 기간.

### Issue (이슈)

- 정의: 관리자가 자체 작성한 중립 질문과 배경 설명, 원문 출처로 구성된 토론 주제.
- 상태: `DRAFT`(작성 중) → `REVIEWED`(정확성·편향성·저작권 검수 완료) → `PUBLISHED`(게시) → `CLOSED`(투표 마감). 연장하면 `PUBLISHED`·`CLOSED` → `PUBLISHED`.
- 마감: 관리자가 수동으로 마감할 수 있다. 매일 06:59(Asia/Seoul)에 마지막으로 열린 시각(연장 시각, 없으면 게시 시각)이 그날 0시 전인 `PUBLISHED` 이슈를 자동 마감한다(`IssueAutoCloseScheduler`). 마감된 이슈도 투표자는 결과·의견을 볼 수 있다.
- 연장: 관리자가 `PUBLISHED`·`CLOSED` 이슈를 연장하면 `PUBLISHED`가 되고 연장 시각(`extended_at`)을 남긴다. 연장한 날의 다음 날 06:59에 다시 자동 마감된다.
- 정책: 관리자만 생성·수정한다(권한 검증은 보안 설정에서 `/api/admin/**` 경로를 `ADMIN`에게만 허용하는 방식으로 한다). 비회원 포함 누구나 `PUBLISHED` 이슈를 조회한다. 카테고리를 1개 가진다. 제목은 100자, 배경 설명은 1000자 이하(가안)다.
- 수정: `DRAFT`, `REVIEWED` 상태에서만 내용을 수정할 수 있고, 수정하면 `DRAFT`로 돌아가 다시 검수가 필요하다.
- 불변 조건: 출처(IssueSource)가 1개 이상이어야 `PUBLISHED`가 될 수 있다. 상태는 정해진 순서로만 전이한다.
- 정정: `PUBLISHED`, `CLOSED` 상태에서 배경 설명만 정정할 수 있고 정정 시각을 남긴다.
- 자동 초안: 뉴스 자동 초안(`newsdraft`)은 일반 작성과 같은 `DRAFT` 이슈를 만든다(자동 생성 표시는 없다). 언론사 8곳의 정치·경제·사회·국제 면 기사(지난 24시간, 피드마다 시간대별로 고르게 최대 12건)로 분야(카테고리)마다 1건씩(`news-draft.drafts-per-category`, 쟁점이 없는 분야는 건너뜀), 관심도는 보도량(다룬 언론사 수)으로 판단하고, 면이 따로 없는 '생활'은 사회·경제 면의 일상 주제에서 고르며, 최근 30개 이슈와 같은 주제는 피하도록 AI에 지시한다. 출처는 수집한 기사 URL만, 언론사·발행일은 피드 값을 쓴다. 기사 제목·요약문은 저장하지 않는다.
- 결정되지 않은 질문: 게시 후 질문 문구 수정 허용 범위, 자동 초안을 목록에서 구분해 표시할지, 쓰지 않은 자동 초안을 지울지.

- 요점(IssueFocus, 2026-10-29): 핵심 쟁점 한 줄(100자), 찬성 측 근거·반대(신중) 측 근거(각 300자). 모두 선택이며, 한쪽만 보이지 않도록 근거는 둘 다 있거나 둘 다 없다(400). 배경 설명은 사실관계만 쓰고 찬반 근거는 요점으로 나눈다. 화면 순서는 핵심 쟁점 → 배경 → 입장별 근거 → 원문 기사 → 투표. 수정 가능 상태(DRAFT, REVIEWED)에서 내용과 함께 바꾼다.
- 대표 이미지: AI가 만든 일러스트 1장(선택). 실존 인물·알아볼 수 있는 얼굴·글자·로고·사진 같은 표현을 쓰지 않고, 찬반 어느 쪽도 좋거나 나쁘게 보이게 그리지 않는다. 화면에는 "AI로 만든 이미지입니다. 실제 장면이 아닙니다."를 함께 보인다. 관리자가 다시 만들거나 지울 수 있다. 게시 전 이슈의 이미지는 관리자만 본다.

### IssueSource (이슈 출처)

- 정의: 이슈의 근거가 된 원문 기사 링크.
- 정책: 원문 URL, 언론사, 발행일을 가진다. 기사 본문·사진은 저장하지 않는다.
- 불변 조건: URL은 http/https 형식이다. 한 이슈 안에서 URL은 중복되지 않는다.

### Category (카테고리)

- 정의: 이슈 분류 (예: 경제, 사회, 생활).
- 정책: 관리자가 관리한다. 목록은 운영 데이터로 관리한다.

### Stance (입장)

- 정의: `AGREE`(찬성), `NEUTRAL`(중립), `DISAGREE`(반대).

### Vote (투표)

- 정의: 회원이 이슈에 대해 선택한 입장.
- 정책: 회원당 이슈별 1회. MVP에서는 변경·취소 불가. `PUBLISHED` 이슈에만 투표할 수 있다.
- 결과: 입장별 투표 수와 비율(소수 첫째 자리 %)을 투표한 회원에게만 공개하고, "서비스 참여자 기준 결과" 고지를 함께 응답한다. 마감된 이슈도 투표자는 결과를 볼 수 있다.
- 불변 조건: `(issueId, memberId)` 유일.

### Opinion (의견)

- 정의: 투표한 회원이 남기는 독립된 의견 글. 다른 의견에 대한 답글이 아니다.
- 정책: 해당 이슈에 투표한 회원만 작성한다. 회원당 이슈별 1개. 수정은 최대 1회. 의견의 입장은 투표 입장과 같다.
- 불변 조건: `(issueId, memberId)` 유일. 내용은 공백일 수 없고 길이 제한이 있다. 작성자만 수정한다.
- 표시: 입장별 탭으로 나눠 추천순 또는 최신순으로 보여주며 작성자 닉네임을 표시한다. 숨김·삭제된 의견은 노출하지 않는다.
- 삭제: 작성자만 삭제한다(삭제 표시, 행은 남김). 삭제한 의견은 수정·추천·신고할 수 없고, 같은 이슈에 의견을 다시 쓸 수 없다(1인 1의견 유지). 내 참여 상태에는 내용 없이 삭제 여부만 응답한다. 관리자 신고 목록에서는 내용을 볼 수 있다.
- 결정되지 않은 질문: 내용 최대 길이(가안 500자).

### Recommendation (추천)

- 정의: 회원이 의견에 표시하는 공감. 비추천은 없다.
- 정책: 해당 이슈에 투표한 회원이 의견당 1회 추천한다(의견 목록이 투표자에게만 공개되므로 같은 기준을 적용). 숨김·삭제된 의견은 추천할 수 없다. 자기 의견은 추천할 수 없다(403). 추천은 취소할 수 있고 취소 후 다시 추천할 수 있다. 추천하지 않은 의견의 취소 요청은 아무 일도 하지 않는다(204).
- 불변 조건: `(opinionId, memberId)` 유일.
- 결정되지 않은 질문: 다른 입장 의견만 추천 가능한지 여부.
- 메모: 기획 원문은 좋아요·싫어요를 MVP에서 제외했으나 2026-10-28 사용자 결정으로 추천(단방향)만 MVP에 포함한다.

### Report (신고)

- 정의: 회원이 부적절한 의견을 관리자에게 알리는 것.
- 상태: `RECEIVED` → `RESOLVED_HIDDEN`(의견 숨김) 또는 `RESOLVED_DISMISSED`(기각).
- 정책: 로그인 회원이 숨김 처리되지 않은 의견을 회원당 의견별 1회 신고한다. 관리자가 처리한다. `RECEIVED` 상태에서만 처리할 수 있다. 숨김 처리 시 해당 의견을 숨기고, 같은 의견의 다른 `RECEIVED` 신고도 `RESOLVED_HIDDEN`으로 종결한다.
- 관리자 직접 조치: 신고 없이도 관리자가 의견을 숨길 수 있다. 숨긴 의견 목록에서 숨김을 해제할 수 있다. 해제해도 이미 처리된 신고의 상태(`RESOLVED_HIDDEN`)는 기록으로 남는다.
- 사유: 사유 목록이 정해지기 전까지 300자 이하 자유 입력(가안).
- 결정되지 않은 질문: 신고 사유 목록, 누적 신고 시 자동 숨김 여부.

### ParticipationEvent (참여 이벤트)

- 정의: 참여 지표 측정용 운영 로그. 코드: `src/main/java/com/ilililissue/metrics/`
- 이벤트: `ISSUE_VIEWED`(브라우저가 이슈 상세를 열면 `POST /api/issues/{id}/views`로 기록, 비회원 포함, 방문자 쿠키 값을 함께 저장), `VOTED`, `OPINION_WRITTEN`, `OPINIONS_VIEWED`(입장 탭 첫 페이지 조회, 회원의 투표 입장과 탭 입장을 함께 기록).
- 지표(관리자 `GET /api/admin/metrics?from&to`, Asia/Seoul 날짜 기준 양 끝 포함):
  - 투표율 = 투표 수 / 이슈별 고유 방문자 수 ((이슈, 방문자 쿠키) 쌍의 수. 같은 브라우저가 같은 이슈를 여러 번 열면 1). 전체 조회 수도 함께 응답한다
  - 웹은 이슈 상세 화면에서 조회 기록을 보낸다(쿠키). 앱은 설치 시 만든 UUID를 `X-Visitor-Id` 헤더로 보낸다. 호출하지 않으면 투표율이 100%를 넘을 수 있다
  - 방문자 쿠키: `visitor_id`(임의 UUID, HttpOnly, SameSite=Lax, 1년). 개인정보를 담지 않는다. 쿠키를 지우거나 기기를 바꾸면 다른 방문자로 센다
  - 의견 작성률 = 의견 작성 수 / 투표 수
  - 반대 의견 열람률 = 자기 입장과 다른 입장 탭을 연 투표자 수 / 투표자 수 (중립↔찬성도 "다른 입장"으로 센다)
  - 7일 재방문율 = 기간 시작 ~ 기간 끝 7일 전에 처음 활동한 회원 중, 첫 활동 7일 이후에 다시 활동한 회원 비율 (회원 이벤트 기준)
- 보관: 1년(가안). `EventRetentionScheduler`가 매일 04:00(Asia/Seoul)에 `occurredAt`이 1년 지난 이벤트를 지운다. 서버가 한 대라는 전제다. 7일 재방문율의 "첫 활동"은 남아 있는 이벤트 기준이므로 1년보다 오래된 회원의 첫 활동은 뒤로 밀린다
- 결정되지 않은 질문: 보관 기간 확정(바꾸면 `/privacy` 2장도 고친다). 쿠키 고지는 `/privacy` 4장 초안. 반대 의견 열람률에서 중립을 반대로 볼지 여부.

## 결정되지 않은 질문 (공통)

- 다중 계정 조작 탐지 기준
- 개인정보 처리방침: 초안 `web/src/app/privacy/page.tsx`. 운영자·보호책임자·연락처·클라우드 사업자·이용 기록 보관 기간·시행일이 대괄호로 비어 있고, 법률 검토 전이다
- 이용약관: 초안 `web/src/app/terms/page.tsx`(금지 행위, 신고·차단·숨김 조치). 운영자·연락처·시행일이 대괄호로 비어 있고 법률 검토 전이다. "반복 위반 회원 이용 제한"을 적었지만 회원 정지 기능은 아직 없다
