# 프로젝트 목표

이 문서는 ilililissue(1일 1이슈)의 목표, 제외 범위, 완료 기준을 정의합니다. 기획 원문은 [docs/planning-2026-10-28.md](./docs/planning-2026-10-28.md)에 있습니다.

## 프로젝트 개요

- 이름: ilililissue (서비스명: 1일 1이슈)
- 목적: 매일 선정한 사회·경제·생활 이슈에 대해 사용자가 찬성·중립·반대 입장을 선택하고 의견을 독립적으로 기록해, 입장별로 서로 다른 생각을 비교하게 한다.
- 제품 원칙: '누가 이겼는지 보여주는 서비스'가 아니라 '사람들이 왜 다르게 생각하는지 보여주는 서비스'.
- 주요 사용자: 사회 이슈에 대한 자기 입장을 남기고 다른 입장의 생각을 읽고 싶은 일반 사용자, 이슈를 등록·검수하는 관리자.
- 핵심 사용 흐름:
  1. 오늘의 이슈 확인 (자체 작성한 중립 질문, 짧은 배경 설명, 원문 기사 링크)
  2. 찬성·중립·반대 중 하나로 투표 (로그인 필요)
  3. 선택적으로 의견 1개 작성 (투표만 참여 가능)
  4. 투표 후 참여 비율과 입장별 의견 확인
  5. 다른 입장의 의견을 읽고 다음 이슈에 재방문

## 해야 하는 일 (MVP)

- 회원가입, 로그인, 로그아웃
- 이슈 목록 및 상세 조회 (비회원 허용)
- 관리자 이슈 등록, 카테고리 지정, 출처 관리, 검수 상태 관리
- 찬성·중립·반대 투표
- 이슈별 의견 작성 1회 및 수정 1회
- 입장별 의견 목록 (추천순/최신순 정렬)
- 의견 추천
- 투표 결과 집계 (투표한 사용자에게만 공개)
- 신고 및 최소한의 관리자 콘텐츠 관리
- 중복 참여 방지 및 기본 운영 로그 (참여 지표 측정용 이벤트 포함)

## 하지 말아야 하는 일

- 대댓글, 직접 답글, 개인 메시지를 만들지 않는다.
- 의견 비추천(싫어요)을 만들지 않는다.
- IP만으로 사용자를 식별하거나 글 소유권을 이전하지 않는다.
- 기사 본문·사진을 복사 게시하지 않는다. 자체 작성한 요약과 원문 링크만 사용한다.
- 통계를 대표성 있는 여론조사처럼 표현하지 않는다.
- 뉴스 API·RSS 자동 수집과 AI 초안 작성은 MVP 범위가 아니다.

## 완료 기준

- 실행 방법과 검증 방법이 문서화되어 있다.
- 핵심 사용 흐름(이슈 확인 → 투표 → 의견 작성 → 입장별 의견 열람)이 API로 동작한다.
- 미정인 도메인 정책은 구현이나 DB 구조로 확정되지 않았다.

## 4주 검증 계획과 실험 목표

- 1주 차 핵심 기능 구현, 2주 차 게시 시작·외부 사용자 모집, 3주 차 지표 측정, 4주 차 유지·개선·중단 판단
- 가설 목표: 누적 방문자 1,000명, 방문 대비 투표율 25%, 투표자 대비 의견 작성률 15%, 7일 후 재방문율 15%, 반대 의견 열람률 30%

## 결정되지 않은 질문

- 초기 카테고리 목록과 하루 게시 개수 (가설: 하루 3개, 경제·사회·생활) — 코드가 아닌 운영 데이터로 관리
