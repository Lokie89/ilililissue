# 에이전트 하네스 아키텍처

## 계층 구분

| 계층 | 책임 | 현재 상태 |
| --- | --- | --- |
| 지침 | 목표, 역할, 정책, 완료 조건 | 모델별 문서로 구현됨 |
| 컨텍스트 | 관련 파일과 로컬 정책 탐색 | 모델별 문서로 구현됨 |
| 도구·권한 | 도구 스키마, 승인, 격리 | 제품 런타임에 의존하며 문서 정책만 있음 |
| 오케스트레이션 | 단계, 분기, 위임, 병렬 처리 | 상태 머신과 역할 문서만 있음 |
| 상태 | checkpoint, 중단, 재개, 세션 상태 | handoff 문서만 있고 런타임 상태 저장은 없음 |
| 안전장치 | 입력·출력·도구 호출 차단 | 승인 기준만 있고 자동 guardrail은 없음 |
| 종료·예산 | 턴, 시간, 도구 호출, 토큰 한도 | 공통 계약으로 정의하며 강제 런타임은 없음 |
| 관측성 | trace, 지연시간, 비용, 오류 | 실행 기록 스키마만 있고 수집기는 없음 |
| 평가 | fixture, rubric, 회귀 판정 | 문서 fixture와 공통 구조화 fixture가 있음 |
| 운영 | worker, queue, secrets, CI, 배포 | 미구현 |

## 실행 생명주기

```text
received
  -> classified
  -> planned
  -> awaiting_approval | running
  -> validating
  -> completed | failed | blocked | cancelled | budget_exhausted
```

- 각 실행은 고유한 `run_id`, fixture 또는 요청 식별자, 시작·종료 시각을 가진다.
- 외부 상태를 바꾸는 도구 호출은 승인 정책을 통과한 뒤 실행한다.
- 중단 가능한 단계에서는 재개에 필요한 checkpoint를 저장한다.
- 성공 여부는 최종 문장보다 검증 결과와 위반 사항으로 판정한다.

## 종료 조건

모든 자동 실행은 무한 반복을 막기 위해 다음 한도를 명시해야 한다.

- `max_turns`: 모델 판단 반복 횟수
- `max_tool_calls`: 전체 도구 호출 횟수
- `timeout_seconds`: 전체 실행 제한 시간
- `max_repeated_failures`: 같은 실패의 허용 반복 횟수
- `max_tokens`: 선택적 토큰 예산

한도를 넘으면 성공으로 포장하지 않고 `budget_exhausted` 또는 `failed`로 종료한다.

## 오류와 재시도

- 일시적 오류만 제한된 횟수와 backoff로 재시도한다.
- 권한 거절, 잘못된 입력, 정책 위반은 자동 재시도하지 않는다.
- 외부 상태를 바꾸는 작업은 idempotency key 또는 중복 방지 근거가 없으면 자동 재시도하지 않는다.
- 같은 오류가 `max_repeated_failures`에 도달하면 사용자 입력이나 환경 변경이 필요한지 판정한다.

## Human-in-the-loop

다음 행동은 실행 전 승인 또는 명확한 사전 승인 범위를 요구한다.

- 데이터 삭제와 되돌리기 어려운 마이그레이션
- 강제 푸시와 공유 브랜치 변경
- PR·이슈 생성, 외부 메시지 발송
- 비용이 발생하는 배포나 외부 서비스 변경
- 비밀값, 개인정보, 권한 경계를 다루는 고위험 작업

승인 대기 상태에는 대상, 예상 영향, 되돌리기 방법, 요청 시점과 결정 결과를 기록한다.

## 멀티 에이전트 계약

- 단순 작업은 단일 에이전트를 기본으로 한다.
- 서브에이전트는 경계가 명확한 탐색, 테스트, 로그 분석, 독립 리뷰에 우선 사용한다.
- 위임 입력에는 목표, 범위, 읽기·쓰기 권한, 기대 산출물, 종료 조건을 포함한다.
- 같은 파일을 수정하는 병렬 작업은 피하고 필요하면 별도 worktree를 사용한다.
- 부모는 하위 결과를 그대로 신뢰하지 않고 근거와 검증 결과를 확인한 뒤 병합한다.
- 의견 품질을 높이기 위한 숙의 작업은 `deliberation.md`의 독립 의견, 비판, 수정, 합성, 검증 라운드를 따른다.
- 숙의형 작업에서 Orchestrator는 첫 라운드 독립성을 보장하고, Critic의 반례와 Synthesizer의 근거 기반 판정을 분리한다.

## 관측성과 개인정보

- trace에는 상태 전이, 모델 호출 메타데이터, 도구 이름, 결과 상태, 검증 결과를 남긴다.
- 토큰, 비밀값, 개인정보, 파일 전체 내용은 기본 trace에 저장하지 않는다.
- 민감한 도구 인자는 마스킹하고 보존 기간과 접근 권한을 운영 정책으로 정한다.
- 실행 재현에 필요한 정보와 민감정보 최소화가 충돌하면 최소 수집을 우선한다.

## 런타임 도입 시 필요한 사용자 결정

- 단일 에이전트 SDK 또는 그래프 기반 런타임
- 로컬 파일, 데이터베이스 또는 외부 trace 서비스
- trace 보존 기간과 민감정보 정책
- 실행별 시간·토큰·비용 기본 한도
- 자동 실행 가능한 도구와 항상 승인받을 도구
- CI에서 실행할 fixture 범위와 허용 비용
