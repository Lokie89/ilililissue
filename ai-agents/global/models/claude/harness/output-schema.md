# 산출물 스키마

이 문서는 Claude가 남겨야 하는 산출물의 필수 구조를 정의한다. 실제 응답은 자연어로 작성할 수 있지만, 아래 의미를 빠뜨리면 안 된다.

## 세션 첫 응답 산출물

새 세션에서 사용자에게 보내는 첫 응답은 현재 요청의 산출물에 더해 아래 내용을 짧게 포함한다. 이전 기록이 없거나 해당 항목이 없으면 `없음`으로 명시한다.

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `recent_work` | 필수 | 최신 handoff 기록에 근거한 최근 작업 요약 |
| `in_progress` | 필수 | 실제로 이어서 진행 중인 내용 또는 `없음` |
| `remaining_work` | 필수 | 기록된 남은 작업 또는 `없음` |

이 요약은 최신 글로벌 기록과 현재 요청의 로컬 프로젝트 기록을 함께 확인해 작성하며, 첫 응답 뒤에는 반복하지 않는다.

## 청사진 산출물

청사진 요청 또는 구현 전 계획에는 아래 항목이 필요하다(`ExitPlanMode` 제출 내용과 대응한다).

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `purpose` | 필수 | 사용자의 요청을 한 문장으로 재정의 |
| `scope` | 필수 | 포함 범위와 제외 범위 |
| `domain_policy` | 조건부 필수 | 새 개념, 상태, 권한, 생명주기 관련 확인 내용 |
| `architecture_policy` | 조건부 필수 | 기술 스택, 배포 구조, 데이터 저장소, 통신 방식, 운영 전제 관련 확인 내용 |
| `approach` | 필수 | 단계별 작업 방식 |
| `expected_changes` | 필수 | 바뀔 파일, 동작, 문서 구조 |
| `side_effects` | 필수 | 기능, 데이터, 성능, 보안, 운영 영향 |
| `validation` | 필수 | 실행할 테스트, 빌드, 린트, 문서 검증 |
| `open_questions` | 조건부 필수 | 임의 결정 위험이 큰 질문(`AskUserQuestion` 대상) |

## 구현 결과 산출물

작업 완료 보고에는 아래 항목이 필요하다.

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `changed_files` | 필수 | 변경한 파일 목록 |
| `summary` | 필수 | 핵심 변경 내용 |
| `domain_policy` | 조건부 필수 | 확인한 정책, 수정한 로컬 정책, 남은 질문 |
| `model_routing` | 조건부 필수 | 역할별 모델/추론 강도 선택 근거, 위임한 서브에이전트나 Workflow |
| `validation_run` | 필수 | 실행한 검증 명령과 결과 |
| `validation_skipped` | 조건부 필수 | 실행하지 못한 검증과 이유 |
| `cleanup` | 조건부 필수 | 정리한 사용하지 않는 코드 또는 정리하지 않은 이유 |
| `remaining_work` | 조건부 필수 | 남은 작업, 리스크, 후속 결정 |

## 프로젝트 생성 결과 산출물

새 프로젝트 생성 완료 보고에는 구현 결과 산출물에 더해 아래 의미를 포함한다. 새 프로젝트 생성이나 초기 세팅은 청사진 승인 뒤에만 실제 파일 생성 완료 보고로 이동한다.

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `project_location` | 필수 | 생성된 프로젝트 경로 |
| `local_harness` | 필수 | 생성 또는 갱신한 `local/<project-name>/` 문서 |
| `run_command` | 필수 | 사용자가 바로 실행할 명령 |
| `test_command` | 조건부 필수 | 테스트 또는 대체 검증 명령 |
| `architecture_blueprint` | 필수 | 현재 기준의 기술 스택, 배포 단위, 데이터 저장소, 운영 전제와 미정 항목 |
| `env_requirements` | 조건부 필수 | 필요한 환경변수와 비밀값 기록 방식 |
| `implemented_flow` | 필수 | 동작하는 핵심 흐름 |
| `known_unknowns` | 조건부 필수 | `미정`으로 남긴 정책, 기능, 검증 |

## 로컬 하네스 대화 산출물

로컬 규칙이 없거나 부족한 프로젝트에서 구현 전에 `AskUserQuestion` 질의가 필요하면 아래 의미를 포함한다.

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `project_type` | 필수 | 새 프로젝트, 기존 프로젝트, 단순 분석 중 분류 |
| `missing_local_context` | 필수 | 없는 로컬 문서나 부족한 정책 |
| `bootstrap_blueprint` | 조건부 필수 | 새 프로젝트 또는 초기 세팅이면 파일 생성 전에 제시할 목적, 범위, 아키텍처, 로컬 하네스, 검증 청사진 |
| `required_questions` | 필수 | 구현 전에 답이 필요한 최소 질문 |
| `architecture_questions` | 조건부 필수 | 아키텍처 청사진이 없거나 부족할 때 필요한 기술 스택, 서버 구성, 데이터 저장소, 운영 질문 |
| `assumptions_allowed` | 조건부 필수 | 사용자가 이미 준 정보로 확정 가능한 항목 |
| `unknowns_to_record` | 조건부 필수 | 답이 없으면 `미정`으로 남길 항목 |
| `local_files_to_create` | 조건부 필수 | 생성 또는 갱신할 `local/<project-name>/` 문서 |
| `next_step` | 필수 | 답변 후 로컬 하네스 생성, 구현 진행, 또는 추가 질의 |

## 리뷰 산출물

리뷰 요청에는 아래 순서로 응답한다. 정형 출력이 요구되면 `ReportFindings`를 사용한다.

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `findings` | 필수 | 버그, 회귀, 테스트 갭, 정책 위반을 심각도순으로 정리 |
| `references` | 필수 | 파일과 줄 번호 |
| `open_questions` | 조건부 필수 | 요구사항이나 정책 확인 질문 |
| `test_gaps` | 조건부 필수 | 검증하지 못한 부분 |
| `summary` | 선택 | 변경 요약 |

## Workflow 위임 산출물

`Workflow`를 사용했다면(opt-in이 확인된 경우) 아래 의미를 포함한다.

| 항목 | 필수 여부 | 내용 |
| --- | --- | --- |
| `opt_in_evidence` | 필수 | opt-in을 확인한 근거(키워드, 세션 설정, 사용자 표현, 슬래시 커맨드) |
| `workflow_scope` | 필수 | 팬아웃 규모와 단계 구성 |
| `dropped_coverage` | 조건부 필수 | 상한선으로 인해 누락된 범위(있다면) |
| `synthesis` | 필수 | 여러 서브에이전트 결과를 종합한 최종 판단 |

## Handoff 기록 산출물

문서, 정책, 하네스, 장기 작업, 다음 세션 인계가 필요한 변경은 `handoff-log.md`에 아래 항목을 남긴다.
단순 질의나 작은 단일 변경처럼 인계 가치가 낮은 작업은 최종 보고로 대체할 수 있다.

에이전트 간 토론을 사용했다면 최종 결론에서 문서화 대상 여부를 판단한다. 결정, 정책, 아키텍처 전제, 검증 기준, 실패 케이스, 산출물 형식, 남은 리스크, 후속 질문이 바뀐 경우에는 라운드 요약 로그만으로 끝내지 않고 적절한 durable 문서나 `handoff-log.md`에 반영한다.

```text
### YYYY-MM-DD

- 목표:
- 변경:
- 검증:
- 남은 작업:
- 주의 사항:
```

날짜는 작업 세션의 실제 날짜를 사용한다.
